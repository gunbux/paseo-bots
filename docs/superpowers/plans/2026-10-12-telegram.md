# Telegram channel implementation plan

> **For agentic workers:** Execute inline using executing-plans. Follow the approved design and test each deliverable before proceeding.

**Goal:** Telegram private messages resume a persistent Voyager chat on legion-nix.

**Architecture:** A plugin-owned polling loop persists updates, dispatches them through a bot-specific runtime adapter, and sends a durable outbox. Lifecycle events supply completed replies and permission notices. Nix pins the tested branch commit from the user-requested GitHub fork.

**Tech stack:** TypeScript, Node fetch, Zod, Vitest, NixOS, Home Manager, SOPS.

**Spec:** ../specs/2026-10-12-telegram-design.md

## Global constraints

- Keep Paseo >=0.9.2 compatibility and runtime imports confined to server/.
- Token values never enter the Nix store, agent prompts, logs or argv.
- Only allowed private users/chats reach the configured bot.
- Persist before acknowledging or dispatching; never replay uncertain side effects.
- No NixOS activation or daemon restart.
